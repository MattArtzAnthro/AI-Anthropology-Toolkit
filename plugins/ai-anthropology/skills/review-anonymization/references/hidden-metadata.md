# Hidden Metadata and the Verification Search

Reference file for the review-anonymization skill. Loaded when clearing
what the file carries beyond its visible text, and when running the
verification search over the finished copy.

A `.docx` is a zip archive of XML parts, and the author's name can sit in
several of them while the body text is clean. The verification search
therefore reads every part, not the page.

---

## 1. Where Identity Hides in a Word File

| Part | What can identify the author |
|---|---|
| `docProps/core.xml` | Author (`dc:creator`), Last modified by (`cp:lastModifiedBy`), title, subject, keywords, description |
| `docProps/app.xml` | Company, Manager |
| `docProps/custom.xml` | Any custom property, including ones written by citation managers and converters |
| `word/comments.xml`, `word/people.xml` | Comment authors and initials; `people.xml` can hold account identifiers |
| `word/document.xml` | Tracked-change authors on insertions and deletions; image alt text and image names |
| `word/header*.xml`, `word/footer*.xml` | Running heads with a surname, file paths in a field |
| `word/footnotes.xml`, `word/endnotes.xml` | Acknowledgement notes, self-citations in notes |
| `word/_rels/*.rels` | Hyperlink targets, including URLs whose display text shows no name |
| `word/media/*` | Image file names, and embedded image metadata such as a camera owner or artist field |

## 2. How Each Tool Fills the Properties

- **Word** stamps Last modified by with the current user's name on every
  save, and fills Author from the user profile when it creates a file. A
  copy that was cleared and then saved again in Word carries the name
  again unless the privacy setting below is on.
- **python-docx** never reads the user's identity. Its default template
  sets Author to "python-docx," the description to "generated by
  python-docx," and a created date in 2013. Editing an existing file keeps
  that file's fields, including the original author's name. Clear the
  fields explicitly in any script.
- **pandoc** never reads the user's identity either, but it writes the
  source document's own `author` metadata into Author, and other metadata
  fields into custom properties. A Markdown master with an author block
  produces a named `.docx`.

## 3. Clearing It

1. In the anonymized copy only, clear Author, Last modified by, title,
   subject, keywords, description, Company, Manager, and custom
   properties.
2. Turn on the privacy setting, in the anonymized copy only:
   - Word for Mac: Review > Protect Document > "Remove personal
     information from this file on save."
   - Word for Windows: File > Info > Check for Issues > Inspect Document,
     then remove Document Properties and Personal Information.

   With the setting on, Word saves without the author fields and shows
   comment and tracked-change authors as "Author." It is stored in
   `word/settings.xml` as `removePersonalInformation`, which the search
   below checks. Leave it off in the master, or the master loses its own
   record.
3. Settle comments and tracked changes. Accept or reject every tracked
   change and delete every comment the venue should not see; a surviving
   comment thread is a conversation between named co-authors. The
   toolkit's `extract_document_markup` MCP tool lists what remains.
4. Check headers and footers, image alt text and image names, and
   hyperlink targets as well as their display text.
5. Check embedded images for metadata. A field photograph can carry the
   photographer's name and also GPS coordinates; the coordinates are a
   participant and fieldsite matter, so raise them with the author rather
   than deciding.
6. If the upload is a PDF, check its Author and Creator fields as well; a
   PDF exported from Word copies the document's properties.

Left alone on purpose: document language and proofing tags, editing-session
identifiers, and style names. They identify nothing.

## 4. The Verification Search

Run it on the copy that will be uploaded, **after its last save.** Put
every string from the Step 1 inventory in `TERMS`: names and variants,
initials, handles, ORCIDs, affiliations, and URL fragments. Standard
library only.

```python
import html, re, sys, zipfile

PATH = sys.argv[1]
TERMS = ["Dana Reyes", "Reyes", "D.R.", "dreyes", "0000-0000-0000-0000",
         "Riverside University"]          # the Step 1 inventory
OK_PLACEHOLDER = re.compile(r"Author \d+( and co-author| et al\.)?")

def text_of(xml):
    # Join runs inside each paragraph so a name split across runs is found.
    paras = re.split(r"</w:p>|</a:p>", xml)
    return "\n".join(html.unescape(re.sub(r"<[^>]+>", "", p)) for p in paras)

with zipfile.ZipFile(PATH) as z:
    for name in z.namelist():
        hay = name                        # media file names count too
        if not name.endswith((".xml", ".rels")):
            hay += "\n" + z.read(name).decode("latin-1")   # e.g. EXIF Artist
        else:
            raw = z.read(name).decode("utf-8", "replace")
            hay += "\n" + html.unescape(raw) + "\n" + text_of(raw)
            if name == "word/settings.xml" and "removePersonalInformation" not in raw:
                print("settings: privacy setting is OFF")
            for m in re.finditer(r"\[(Author[^\]]*)\]", text_of(raw)):
                if not OK_PLACEHOLDER.fullmatch(m.group(1)):
                    print(f"{name}: placeholder holds extra text: [{m.group(1)}]")
        for term in TERMS:
            for m in re.finditer(re.escape(term), hay, re.I):
                ctx = hay[max(0, m.start() - 40):m.end() + 40].replace("\n", " ")
                print(f"{name}: {term!r} ... {ctx}")
```

What it reports:

- **Every hit, with the part it is in.** A hit can print twice, once from
  the raw XML and once from the joined paragraph text. A name split across
  runs appears only in the joined text.
- **The privacy setting** if it is off.
- **Placeholders that swallowed neighbouring text,** such as `[Author 1
  2021 market]`, the usual result of a hand paste landing in the wrong
  place. Read the sentence around every placeholder as well: a paste that
  replaced the wrong span can leave a well-formed bracket beside a
  sentence missing its words.

Short terms such as initials produce false hits inside other words.
Report them and let the author dismiss them; do not drop a term from the
search to make the report quiet.

## 5. Reporting

One sentence saying what ran, then the hits by part. Anything that could
not run is reported as unrun: a PDF whose metadata could not be read, an
image format the search cannot see inside, a file in a format other than
`.docx`. A search that read only the body text is reported as partial,
never as clean.
